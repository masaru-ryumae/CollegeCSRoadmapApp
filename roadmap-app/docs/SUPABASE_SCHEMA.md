# Supabase Database Schema

This document describes the database schema for the College CS Roadmap application.

## Tables

### users
Stores user account information and preferences.

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | User ID (auto-generated by Supabase Auth) |
| email | text | UNIQUE, NOT NULL | User email address |
| name | text | | User display name |
| invite_code | text | | Invite code used during registration (if applicable) |
| created_at | timestamp | NOT NULL | Account creation timestamp |
| updated_at | timestamp | | Last update timestamp |
| preferences | jsonb | | User preferences (e.g., theme, notification settings) |

**Indexes:**
- `idx_users_email` on `email`
- `idx_users_created_at` on `created_at`

---

### progress
Tracks user progress through modules.

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | Progress record ID |
| user_id | uuid | FOREIGN KEY (users.id), NOT NULL | Reference to user |
| module_id | text | NOT NULL | Module identifier |
| completed | boolean | DEFAULT false | Whether module is completed |
| time_spent | integer | DEFAULT 0 | Time spent on module (in minutes) |
| weekly_schedule | jsonb | | Weekly schedule data (e.g., days/hours planned) |
| deadline | timestamp | | Target completion deadline |
| completed_at | timestamp | | Actual completion timestamp |
| created_at | timestamp | NOT NULL | Record creation timestamp |
| updated_at | timestamp | | Last update timestamp |

**Constraints:**
- `UNIQUE(user_id, module_id)` - One progress record per user per module

**Indexes:**
- `idx_progress_user_id` on `user_id`
- `idx_progress_module_id` on `module_id`
- `idx_progress_user_module` on `(user_id, module_id)`

---

### resources
Community-contributed learning resources.

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | Resource ID |
| module_id | text | NOT NULL | Associated module |
| type | text | NOT NULL | Resource type (e.g., 'video', 'article', 'tutorial', 'tool') |
| url | text | NOT NULL | Resource URL |
| title | text | NOT NULL | Resource title |
| description | text | | Resource description |
| created_by | uuid | FOREIGN KEY (users.id) | User who submitted resource |
| approved | boolean | DEFAULT false | Whether resource is approved by moderators |
| approved_at | timestamp | | Approval timestamp |
| created_at | timestamp | NOT NULL | Submission timestamp |
| updated_at | timestamp | | Last update timestamp |

**Indexes:**
- `idx_resources_module_id` on `module_id`
- `idx_resources_approved` on `approved`
- `idx_resources_created_by` on `created_by`

---

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | Suggestion ID |
| user_id | uuid | FOREIGN KEY (users.id), NOT NULL | User who made suggestion |
| module_id | text | NOT NULL | Associated module |
| title | text | NOT NULL | Suggested resource title |
| description | text | | Suggested resource description |
| url | text | | Suggested resource URL |
| resource_type | text | | Suggested resource type |
| status | text | DEFAULT 'pending' | Status ('pending', 'approved', 'rejected') |
| feedback | text | | Moderator feedback |
| created_at | timestamp | NOT NULL | Suggestion timestamp |
| updated_at | timestamp | | Last update timestamp |

**Indexes:**
- `idx_resource_suggestions_user_id` on `user_id`
- `idx_resource_suggestions_status` on `status`
- `idx_resource_suggestions_module_id` on `module_id`

### notifications
User notifications for progress updates and community activities.

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | Notification ID |
| user_id | uuid | FOREIGN KEY (users.id), NOT NULL | Recipient user |
| type | text | NOT NULL | Notification type (e.g., 'progress', 'reminder', 'community') |
| title | text | NOT NULL | Notification title |
| message | text | | Notification message |
| related_module_id | text | | Associated module (if applicable) |
| is_read | boolean | DEFAULT false | Whether notification has been read |
| read_at | timestamp | | When notification was read |
| created_at | timestamp | NOT NULL | Creation timestamp |
| expires_at | timestamp | | Expiration timestamp (for temporary notifications) |

**Indexes:**
- `idx_notifications_user_id` on `user_id`
- `idx_notifications_is_read` on `is_read`
- `idx_notifications_created_at` on `created_at`

---

### invite_codes
Invite codes for controlling app access.

| Column | Type | Constraints | Description |
|--------|------|-----------|-------------|
| id | uuid | PRIMARY KEY | Invite code ID |
| code | text | UNIQUE, NOT NULL | The actual invite code string |
| created_by | uuid | FOREIGN KEY (users.id) | Admin who created the code |
| uses_remaining | integer | | Number of times code can be used (-1 for unlimited) |
| expires_at | timestamp | | Code expiration date |
| created_at | timestamp | NOT NULL | Creation timestamp |
| required | boolean | DEFAULT false | Whether app requires invite codes for signup |

**Indexes:**
- `idx_invite_codes_code` on `code`
- `idx_invite_codes_expires_at` on `expires_at`

## Foreign Key Relationships

```
users (id)
  ├── progress (user_id)
  ├── resources (created_by)
  ├── resource_suggestions (user_id)
  ├── notifications (user_id)
  └── invite_codes (created_by)
```

## Row-Level Security (RLS) Policies

### users table
- Users can view their own profile
- Users can update their own profile
- Public can read non-sensitive user info (name only)

### progress table
- Users can only view/update their own progress records
- Admins can view all progress records

### resources table
- Anyone can view approved resources
- Users can create new resources
- Admins can approve/reject resources

### notifications table
- Users can only view their own notifications
- System can create notifications
- Users can update read status of their own notifications

### invite_codes table
- Only admins can view/create invite codes
- System validates codes during signup

## Triggers and Functions

### on_auth_user_created
Automatically creates a user profile when a new authentication user is created.

```sql
CREATE OR REPLACE FUNCTION public.handle_new_user() 
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.users (id, email, name, created_at, updated_at)
  VALUES (new.id, new.email, new.raw_user_meta_data->>'name', NOW(), NOW());
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

## Data Types

- **uuid**: Unique identifier (auto-generated by default)
- **text**: Variable-length text string
- **integer**: Whole number
- **boolean**: True/False value
- **timestamp**: Date and time with timezone
- **jsonb**: JSON data (binary format, indexed)

---

## Notes

- All timestamps use UTC timezone
- Soft deletes can be implemented using `deleted_at` timestamps if needed
- `updated_at` columns should be auto-updated using database triggers
- Consider adding `soft_delete` columns for audit trails in production
